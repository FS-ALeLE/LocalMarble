# LocalMarble 기획서 — 「홍성 탐험 고고!」

> 지역 행사 부스에서 초등학생이 주사위를 굴려 지도를 돌며, 그 지역 퀴즈와 미니게임으로 지역을 배우는 디지털 보드게임.
> 첫 지역: **충청남도 홍성군**
> 구조 참고: 아케이드 퀴즈 게임 「데이트 퀴즈 고고」(SemiCom, 1998). 지도를 이동하며 장소별 퀴즈와 미니게임을 풀고, 라이프가 줄어드는 구조.

### 확정된 사항

| 항목 | 결정 |
|---|---|
| 플레이 인원 | **1인 전용** (2인 대결 모드 없음) |
| 플랫폼 | **웹 브라우저**. 태블릿(가로)과 노트북 화면 대응 |
| 운영 방식 | **행사 모드 하나로 통일**. 모든 기기가 같은 방식(매 판 새로 등록)으로 동작 |
| 그래픽 스타일 | **미니어처 디오라마** |
| 그래픽 제작 | **모든 그래픽을 Claude가 코드로 제작** (3D 모델, SVG 일러스트, 효과, 효과음까지) |
| 첫 화면 | **소속 + 별명** 입력 → 결과를 **행사 리더보드**에 기록 |
| 리더보드 | **행사 기간에만 운영**. 행사별로 따로 집계 |
| DB | **Neon** (서버리스 PostgreSQL) |

## 1. 기획 목표

| 항목 | 내용 |
|---|---|
| 대상 | 초등학생 (저학년 1~3학년 / 고학년 4~6학년 난이도 분리) |
| 사용 환경 | 행사 부스의 태블릿, 노트북 (웹 브라우저) |
| 1판 시간 | **5~7분**. 대기 줄이 생기는 행사 특성을 고려 |
| 학습 목표 | 홍성의 역사 인물, 문화유산, 특산물, 자연, 생활 안전을 놀이로 접함 |
| 동기 부여 | 소속별 리더보드로 "우리 학교가 홍성 박사!" 같은 경쟁 요소 |
| 확장성 | 지역 데이터(지도, 장소, 문항, 그래픽)를 **지역 팩**으로 분리해 다른 시·군으로 확장 (LocalMarble = Local + 부루마블) |

## 2. 핵심 게임 흐름

```
[등록: 소속·별명] → [타이틀] → [난이도·캐릭터 선택] → [보드 진행 루프] → [결과] → [리더보드]
                                                            │
                                                            ├─ 주사위 굴리기 (1~3)
                                                            ├─ 이동 (갈림길이면 방향 선택)
                                                            ├─ 도착 칸 이벤트
                                                            │    ├─ 장소 칸 → 테마 퀴즈 또는 미니게임
                                                            │    ├─ 찬스 칸 → 랜덤 카드
                                                            │    └─ 특수 칸 → 워프·휴식·함정
                                                            ├─ 점수·라이프·도장 갱신
                                                            └─ 종료 조건 확인
```

### 2.1 기본 규칙

- **주사위**: 1~3. 화면의 큰 주사위를 터치(노트북은 클릭 또는 스페이스바)하면 굴러감. 칸 수가 작으므로 보드는 20~26칸 정도로 촘촘하게 설계.
- **라이프**: ♥ 3개로 시작. 퀴즈 오답 또는 미니게임 실패 시 1개 감소.
- **점수(탐험 점수)**: 정답, 미니게임 성공, 찬스 카드로 획득. 리더보드 순위 기준.
- **홍성 도장(스탬프)**: 테마 장소에서 **처음 정답**을 맞히면 그 장소의 도장을 획득. 학습 동기를 주는 수집 요소.
- **종료 조건** (먼저 해당되는 것)
  1. 도장 **5개**를 모은 뒤 **골인 지점(홍주읍성 조양문)** 에 도착 → **완주 성공**
  2. 라이프 0 → 게임 오버. 그때까지의 점수로 리더보드 기록
  3. 턴 제한(기본 12턴) 초과 → 시간 종료. 리더보드 기록
- **이어하기 없음**: 행사 회전율을 위해. 대신 게임 오버 시 "오늘 배운 홍성 이야기" 요약 카드를 보여 줌.

### 2.2 「데이트 퀴즈 고고」 요소 대응표

| 원작 요소 | 이 게임에서의 대응 |
|---|---|
| 데이트 상대의 호감도 | **홍성 안내 캐릭터의 "친해지기 게이지"**. 정답이 쌓이면 캐릭터 대사·표정이 바뀌고 엔딩이 달라짐 |
| 장소마다 다른 퀴즈 | 장소마다 **테마 카테고리** 문항 풀 |
| 퀴즈 사이 미니게임 | 특정 장소는 **미니게임 전용**, 일부 장소는 퀴즈와 미니게임 랜덤 |
| 라이프 | ♥ 3개 |
| 오락실 점수 경쟁 | **온라인 리더보드** (개인 순위 + 소속 순위) |

> 원작의 캐릭터, 그래픽, 명칭, 음악은 사용하지 않고 구조만 참고합니다(저작권).

### 2.3 안내 캐릭터 (예시)

- **"홍이"와 "주니"**: 홍주(홍성의 옛 이름)에서 따온 이름의 탐험 안내자. 선택한 캐릭터가 말풍선으로 문제를 내고 해설을 읽어 줌.
- 홍성군 공식 캐릭터 사용 여부는 군청과 협의(라이선스 확인 필요).

## 3. 시작 등록 · 리더보드

### 3.1 운영 방식: 행사 모드 하나

- 기기 종류와 상관없이 **모든 판이 같은 흐름**: `등록 → 플레이 → 결과 → 리더보드 → "다음 친구 차례!" → 등록`
- 기기에 프로필을 기억하지 않음. 매 판 새로 등록하므로 공용 태블릿·노트북을 여러 아이가 돌려 써도 섞이지 않음.
- 입력 없이 60초가 지나면 등록 화면으로 자동 복귀.
- 접속 주소는 하나: `https://<도메인>/` → 서버에서 **현재 진행 중인 행사**를 자동으로 찾아 연결.

### 3.2 등록 화면 흐름

```
[소속 선택] → [별명 입력] → [확인 카드: "홍성초 · 날쌘대하 맞나요?"] → 타이틀
```

**① 소속**
- 1단계: 유형 고르기 — `학교` / `기관·단체` / `가족·개인`
- 2단계
  - **학교**: 홍성군 초등학교 목록에서 **검색해서 고르기**(예: "홍" 입력 → 홍성초, 홍주초 …). 목록에 없으면 "직접 쓰기".
  - **기관·단체**: 행사마다 진행자가 미리 등록한 목록(지역아동센터, 도서관 프로그램 등) + 직접 쓰기
  - **가족·개인**: `개인`으로 기록 (소속 대항전에서는 제외)
- 학년은 선택 입력 (1~6학년). 고르면 **난이도 기본값**이 자동으로 정해짐(1~3 → 저학년).

**② 별명**
- 2~8자, 한글·영문·숫자만.
- **"추천 별명" 주사위 버튼**: 홍성 낱말 조합으로 자동 생성 (예: `날쌘대하`, `반짝새우젓`, `용감한억새`, `씩씩한조양문`). 글쓰기가 느린 저학년도 바로 시작 가능.
- **금칙어 필터**(욕설, 비하어) + "진짜 이름은 쓰지 마세요" 안내 문구.
- 같은 행사·같은 소속에 같은 별명이 있으면 자동으로 번호를 붙임: `날쌘대하#2`

**③ 화면 표시 형식**: `날쌘대하 · 홍성초` (소속은 줄임말 표시 가능)

### 3.3 행사가 없을 때

- 진행 중인 행사가 없으면 리더보드는 닫히고, 게임만 **연습 모드**로 플레이(등록·기록 없음, 결과 화면까지만).
- 진행자가 시연·점검할 때도 이 상태를 사용.

### 3.4 리더보드 구성 (행사별)

| 탭 | 내용 |
|---|---|
| **오늘의 탐험왕** | 그날 개인 점수 TOP 20 (여러 날 하는 행사용) |
| **행사 전체 순위** | 행사 기간 전체 개인 TOP 20 |
| **소속 대항전** | 소속별 점수 = **상위 5명 평균** (참여 3명 이상인 소속만) |
| **내 순위** | 결과 화면에서 TOP 20 밖이어도 "128명 중 37등"처럼 보여 줌 |

- 순위는 **한 판 = 한 기록**. 같은 아이가 다시 하면 새 별명으로 등록되므로 별도 중복 처리 없음. (진행자가 "1인 1회" 같은 규칙을 정하면 현장 안내로 운영)
- 동점이면 **도장 수 → 걸린 시간 짧은 순**.
- **전광판 화면**: `…/board` 를 부스의 큰 모니터에 띄우면 **5초마다 자동 갱신**, 새 기록이 순위에 들어오면 반짝 효과.
- 행사가 끝나면 리더보드는 **최종 순위 화면으로 고정**되고, 기록 보관 기간이 지나면 삭제(3.7).

### 3.5 서버 · 데이터 (Neon)

**구성**

```
[브라우저: 게임]  ──HTTPS──▶  [서버리스 API 함수]  ──▶  [Neon PostgreSQL]
[브라우저: 전광판] ──5초마다──▶        (Vercel Functions 등)
```

- **Neon**은 DB만 제공하므로, 사이에 **API 함수**를 둠. 게임 화면을 올리는 곳(Vercel 추천, Netlify·Cloudflare도 가능)의 서버리스 함수에서 `@neondatabase/serverless` 드라이버로 접속.
- **DB 접속 주소(비밀번호 포함)는 서버 환경변수에만 저장**하고, 브라우저 코드에는 절대 넣지 않음.
- Neon에는 실시간 구독 기능이 없으므로 전광판은 **짧은 주기 조회(5초)** 로 갱신. 행사 규모(시간당 수십 판)에는 충분.
- Neon 무료 요금제로 행사 규모 운영 가능. DB가 쉬다가 처음 요청 때 잠깐(1초 안팎) 깨어나는 지연이 있으므로, 전광판 조회가 DB를 깨어 있게 하는 효과도 있음.

**API (안)**

| 메서드 · 경로 | 용도 |
|---|---|
| `GET /api/event` | 현재 진행 중인 행사 정보 (없으면 연습 모드) |
| `GET /api/affiliations?q=홍` | 소속 검색 |
| `POST /api/players` | 소속·별명 등록 → 플레이 토큰 발급 |
| `POST /api/plays` | 결과 점수 저장 (플레이 토큰 필요) → 내 순위 응답 |
| `GET /api/leaderboard?tab=today` | 리더보드 조회 |
| `POST /api/admin/...` | 진행자 기능 (비밀번호 확인) |

**테이블(안)**

```sql
events        (id, region, name, starts_at, ends_at, is_active)
affiliations  (id, region, event_id NULL, type, name, short_name)   -- event_id가 있으면 그 행사 전용 기관
players       (id, event_id, affiliation_id, nickname, grade, created_at)
plays         (id, player_id, event_id, score, stamps, lives_left, turns,
               duration_sec, level, finished, created_at)
```

**점수 검사 (서버)**
- 등록 때 발급한 **플레이 토큰**이 있어야 저장 가능, 토큰 하나당 기록 1번.
- 점수가 이론상 최고점을 넘는지, 등록부터 결과까지 시간이 너무 짧지 않은지 검사.
- 별명 금칙어를 서버에서도 한 번 더 검사.

**오프라인 대비**
- 행사장 인터넷이 끊기면 기록을 기기(IndexedDB)에 쌓아 두고, 연결되면 자동 전송. 화면에는 "기록 저장 대기 중" 표시.
- 등록도 오프라인이면 기기에서 임시 토큰으로 진행하고, 전송할 때 서버가 함께 처리.

### 3.6 진행자 관리 화면 (`/admin`)

- 비밀번호 로그인 (비밀번호는 서버 환경변수).
- 행사 만들기·시작·종료, 행사 전용 소속(기관) 추가.
- 부적절한 별명 숨기기, 기록 삭제.
- 게임 설정: 턴 제한, 완주에 필요한 도장 수, 기본 난이도.
- 리더보드 CSV 내보내기 (경품 확인용).

### 3.7 개인정보 원칙

- **실명, 연락처, 사진 등은 받지 않음.** 받는 것은 소속(학교 수준), 별명, 학년(선택)뿐.
- 등록 화면 안내: "별명과 학교 이름이 순위표에 보여요. 진짜 이름은 쓰지 마세요."
- 행사 기록은 **행사 종료 후 정해진 기간(예: 1개월) 뒤 삭제**하고, 문항별 정답률 같은 익명 통계만 남김. 보관 기간은 운영 기관(학교·군청)과 정함.

## 4. 지도(보드) 설계

### 4.1 형태

- 홍성군 실제 지도를 단순화한 **일러스트 맵** 위에 칸을 배치.
- **순환 경로 + 갈림길 2곳**: 갈림길에서 아이가 방향을 고르게 해 "탐험하는 느낌"을 줌.
- 서쪽(바다: 남당항, 스카이타워) / 중앙(홍성읍: 홍주읍성, 시장) / 북쪽(내포신도시, 용봉산) / 남쪽(광천, 오서산) / 동쪽(홍동, 이응노의 집)처럼 **실제 위치 관계를 지켜** 지리 감각도 함께 익히게 함.
- 지도는 화면보다 크게 그리고, **카메라가 말을 따라 이동·확대**함 (7장 연출 참고).

### 4.2 장소 칸 목록 (요청한 장소 + 홍성 특색)

| 장소 유형 | 홍성 이름(안) | 실제 연결 | 테마 / 활동 |
|---|---|---|---|
| 도서관 | **만해 도서관** | 만해 한용운 (결성면 출생, 「님의 침묵」) | 국어·인물: 시인·독립운동가 이야기, 낱말 퀴즈 |
| 경찰서 | **백야 안전지킴이 경찰서** | 백야 김좌진 장군 (갈산면 출생, 청산리 전투) | 생활 안전·교통 규칙 퀴즈 + 김좌진 장군 인물 퀴즈 |
| 박물관 | **홍주성 역사관** | 홍주읍성, 홍주의병 | 역사 퀴즈 (홍주의 옛 이름, 의병, 읍성 구조) |
| 골목길 | **광천 토굴 새우젓 골목** | 광천 토굴 새우젓, 독배마을 | 미니게임 「새우젓 항아리 쌓기」 + 특산물 퀴즈 |

| 관청 | **내포 도청 광장** | 충남도청 소재지(내포신도시) | 우리 지역 사회: 도청이 하는 일, 충남의 시·군 |
| 미술관 | **고암 이응노의 집** | 이응노 화백 생가 기념관 (홍북읍) | 미니게임 「같은 그림 찾기 / 틀린 그림 찾기」 |

| 생가·유적 | **성삼문·최영 장군 이야기길** | 사육신 성삼문, 최영 장군 관련 유적 | 인물 짝 맞추기 미니게임 |

> ⚠️ 모든 지명·인물·사실은 제작 단계에서 **홍성군청 문화관광 자료, 홍주성역사관 자료로 반드시 확인**합니다(6장 참고). 위 표는 기획용 초안입니다.

### 4.3 특수 칸

| 칸 | 효과 |

## 5. 퀴즈 · 미니게임 설계

### 5.1 퀴즈 형식

| 형식 | 설명 | 주 대상 |
|---|---|---|
| **O/X** | 두 개의 큰 버튼 | 저학년 |
| **3지선다 / 4지선다** | 그림 보기 포함 가능 | 공통 |
| **그림 보고 맞히기** | 디오라마 건물·특산물 그림 → 이름 | 공통 |
| **순서 맞히기** | 사건 순서, 새우젓 만드는 과정 등 드래그 정렬 | 고학년 |

- **제한 시간**: 저학년 20초, 고학년 15초. 시간 막대 표시.
- **힌트**: 게임당 1회 "홍이의 힌트"(오답 보기 하나 지우기).
- **정답 해설**: 맞혀도 틀려도 **해설 1~2문장**을 반드시 보여 줌. 학습 효과의 핵심.
- **음성 읽기**: 문제와 해설을 읽어 주는 버튼. 한글 읽기가 느린 저학년용.
- **입력**: 터치, 마우스, 키보드(1~4 숫자 키, O/X 키) 모두 지원.

### 5.2 문항 랜덤 배치 방식

1. 각 장소 칸은 `category`(카테고리)를 가짐. 예: `history`, `people`, `safety`, `specialty`, `nature`, `society`, `environment`
2. 게임 시작 시 선택한 난이도의 문항 풀에서 카테고리별로 **섞은 덱**을 만듦.
3. 그 칸에 멈추면 해당 카테고리 덱에서 **중복 없이** 한 문항을 뽑음(한 판 안에서 같은 문제 안 나옴).
4. 덱이 비면 다시 섞어서 사용.
5. "퀴즈 또는 미니게임" 칸은 정해진 비율(예: 퀴즈 70%, 미니게임 30%)로 결정.
6. 같은 기기에서 직전 판에 나온 문항은 가중치를 낮춰, 다시 하는 아이가 같은 문제만 보지 않게 함.

### 5.3 미니게임 목록 (터치·클릭 한두 번으로 되는 30초 이내 게임)

| 이름 | 장소 | 조작 | 성공 조건 |
|---|---|---|---|
| 대하 잡기 | 남당항, 경기장 | 튀어 오르는 대하를 터치 | 20초 안에 10마리 |
| 새우젓 항아리 쌓기 | 광천 골목 | 타이밍 맞춰 터치해 쌓기 | 5층 쌓기 |
| 달리기 연타 | 경기장 | 버튼 빠르게 연타 (노트북: 스페이스바) | 정해진 시간 안에 결승선 |
| 같은 그림 찾기 | 이응노의 집 | 카드 뒤집기 짝 맞추기 | 제한 시간 안 4쌍 |
| 틀린 그림 찾기 | 홍주성 역사관 | 두 그림 비교 터치 | 3곳 찾기 |
| 인물 짝 맞추기 | 이야기길 | 인물 ↔ 업적 연결 | 3쌍 모두 정답 |
| 장보기 계산 | 전통시장 | 숫자 버튼 | 정답 입력 |
| 용봉산 길 찾기 | 용봉산 | 갈림길 미로를 손가락으로 따라가기 | 정상 도착 |

- 실패해도 라이프만 1 깎이고 **짧은 상식 한 줄**은 보여 줌.
- 1차 개발(MVP)에는 미니게임 **3개**(대하 잡기, 같은 그림 찾기, 장보기 계산)만 구현.

### 5.4 점수 · 보상

| 행동 | 점수 |
|---|---|
| 퀴즈 정답 | +100 (힌트 사용 시 +50) |
| 빠르게 정답(남은 시간 절반 이상) | +30 보너스 |
| 미니게임 성공 | +150 |
| 도장 첫 획득 | +50 |
| 완주 보너스 | +300 + 남은 라이프 × 100 |

- **결과 화면 등급**: 🥉 홍성 새내기 / 🥈 홍성 탐험가 / 🥇 홍성 박사. 등급을 부스 경품(스티커, 엽서 등)과 연결.
- 결과 화면 → **"내 순위 보기"** → 리더보드로 이어짐 (3.4).
- 점수 규칙에서 **한 판의 이론상 최고점**을 계산해 두고, 서버 검사 기준으로 사용 (3.5).

### 6.3 문항 데이터 형식 (JSON)

```json
{
  "id": "hs-people-001",
  "region": "hongseong",
  "category": "people",
  "level": "low",
  "type": "choice",
  "question": "「님의 침묵」을 쓴 홍성 출신 시인은?",
  "choices": ["한용운", "윤동주", "김소월", "정지용"],

```

- `source`(출처)와 `verified`(검수 완료) 필드가 없는 문항은 게임에 나오지 않게 함.

## 7. 그래픽 · 아트 디렉션

### 7.1 스타일: 미니어처 디오라마

- 탁자 위에 놓인 **장난감 홍성 마을 모형**을 비스듬히 내려다보는 느낌.
- 둥글둥글한 건물, 짧고 통통한 비율, 부드러운 그림자, 가장자리가 살짝 흐려지는 **틸트시프트(미니어처 사진) 효과**.
- 장소 13곳이 각각 **작은 건물 모형**이라 아이들이 "저기 가고 싶다"를 그림으로 고를 수 있음.
- 점수 숫자, "READY? GO!", 결과 등급 연출에만 **오락실 느낌**을 살짝 넣어 원작 분위기를 살림.

### 7.2 Claude가 코드로 만드는 그래픽 방식

외부 그림 파일 없이 **모든 그래픽을 코드로 생성**합니다. 그래서 그림 방식을 "코드로 만들었을 때 가장 예쁘게 나오는 방식"으로 고릅니다.

| 대상 | 만드는 방법 | 이유 |
|---|---|---|
| **지도·건물 (디오라마)** | **three.js 3D**: 기본 도형(상자, 원기둥, 원뿔, 둥근 모서리 상자)을 조합한 **로우폴리 장난감 모형** | 코드 3D는 빛·그림자·깊이가 자동으로 생겨 미니어처 느낌이 가장 잘 남. 건물마다 같은 조명을 받아 스타일이 저절로 통일됨 |
| 지형 | 높이값을 코드로 만든 섬 모양 판 (바다, 갯벌, 논, 산) | 홍성 지형을 단순화해 표현 |
| 살아 있는 요소 | 물결(셰이더), 흔들리는 억새, 날아가는 갈매기, 지나가는 장항선 기차 | 화면이 멈춰 있지 않게 |
| 안내 캐릭터 | **SVG** 벡터 그림. 눈·입·눈썹 부품을 바꿔 표정 6종 | 부품식이라 표정이 늘어도 얼굴이 똑같이 유지됨 |
| 플레이어 말 | three.js 3D 소형 모형 (대하, 새우, 한우, 오리 등) | 지도 위에서 통통 뛰는 연출 |
| 도장 13종 | SVG (원·사각 테두리 + 장소 그림 + 글자, 잉크 번짐 필터) | 장소별 통일된 도장 디자인 |
| UI (버튼, 카드, 점수판, 리더보드) | HTML/CSS + SVG 아이콘 | 글자가 선명하고 화면 크기 대응이 쉬움 |
| 효과 | 파티클(별가루, 폭죽, 물보라), CSS·GSAP 애니메이션 | |
| 미니게임 그림 | SVG 또는 2D 캔버스 | 미니게임은 2D로 가볍게 |
| 효과음·배경음악 | **Web Audio API로 소리 합성** (오락실풍 효과음), 배경음악은 코드로 짠 짧은 반복곡 | 소리 파일도 직접 만들 수 있음 |

**코드 그래픽의 한계와 대응**
- **실제 사진은 만들 수 없음** → 5.1의 "사진 보고 맞히기"는 **디오라마 건물이나 SVG 그림 보고 맞히기**로 바꿈. 실제 사진이 꼭 필요하면 공공누리 사진을 출처와 함께 사용.
- 실제 인물 초상화는 그리지 않음 → 인물은 **상징물로 표현**(한용운 → 책과 붓, 김좌진 → 장군 깃발, 이응노 → 붓과 먹 그림 등).
- 글꼴은 만들 수 없으므로 무료 웹폰트 사용 (7.3).

  - 오락실 연출: Galmuri (한글 픽셀 글꼴)
- 문제 글씨는 3D 배경 위에 바로 쓰지 않고 **반투명 카드** 위에 올려 가독성 확보.

### 7.4 연출 (움직임이 그래픽 품질의 절반)

| 장면 | 연출 |
|---|---|
| 주사위 | 3D 주사위가 탁자 위로 던져져 굴러감(물리 흉내, 0.8초), 숫자 확정 시 화면 "쿵" 흔들림 |
| 이동 | 말이 칸마다 **통통 뛰며** 이동, 카메라가 부드럽게 따라감 |
| 장소 도착 | 카메라가 건물로 확대 → 건물이 "뿅" 하고 살짝 커졌다 돌아옴 → 퀴즈 카드가 **펼쳐지듯** 등장 |
| 정답 | 별가루 + 캐릭터 기쁜 표정 + 점수 숫자가 날아가 점수판에 더해짐 |
| 오답 | 카드 좌우 흔들림, 하트가 깨지는 애니메이션, 해설은 차분하게 |
| 도장 획득 | 화면 가운데 **도장 "쾅!"** + 잉크 번짐 + 도장판으로 날아감 |
| 완주 | 조양문이 열리며 폭죽, 등급 메달 회전 |
| 리더보드 진입 | 내 기록 줄이 아래에서 올라와 순위 자리에 "착" 꽂힘 |

### 7.6 제작 순서

1. **스타일 시안(1주)**: 섬 지형 일부 + 건물 2채(홍주성 역사관, 광천 새우젓 골목) + 말 이동 + 퀴즈 카드 1장을 브라우저에서 바로 볼 수 있게 제작 → 확인 후 방향 확정
2. **건물·소품 확장(개발과 병행)**: 시안에서 정한 규칙(크기 단위, 모서리 둥글기, 색 팔레트, 조명)을 **공통 코드 부품**으로 만들어 나머지 건물에 그대로 적용 → 스타일 통일
3. **성능 확인**: 보급형 태블릿에서 프레임 측정. 느리면 그림자 품질·틸트시프트·소품 수를 자동으로 낮춤
4. 그림 파일이 거의 없으므로 **첫 로딩이 가벼움**(글꼴 제외 수 MB 이내 목표)

## 8. 화면 대응 · UX

### 8.1 지원 화면

| 기기 | 해상도 예 | 방향 |
|---|---|---|
| 태블릿 (iPad, 갤럭시 탭) | 1024×768 ~ 2560×1600 | **가로 전용** (세로면 "기기를 가로로 돌려 주세요" 안내) |
| 노트북 | 1366×768 ~ 1920×1080 | 브라우저 창 크기에 맞춤, 전체 화면 버튼 제공 |

- **3D 디오라마는 어떤 화면 비율이든 꽉 채워 그림**(카메라 시야만 조정). 4:3 태블릿에서는 위아래로, 16:9 노트북에서는 좌우로 바다가 조금 더 보임.
- **UI는 기준 크기 1600×1000 (16:10)** 으로 설계하고 화면에 맞게 확대·축소.
  - 점수판, 하트, 주사위 버튼 같은 UI는 화면 가장자리에 붙여 배치(비율이 달라도 안 잘림).
- **선명도**: UI·캐릭터·도장은 SVG라 어떤 해상도에서도 선명. 3D 화면은 고해상도 화면에서 렌더 배율을 최대 2배까지 올리되, 느리면 자동으로 낮춤.
- **지원 브라우저**: Chrome, Safari(iPad), Edge, Samsung Internet 최신 버전.
- **성능 목표**: 보급형 태블릿에서도 초당 60프레임에 가깝게. 느린 기기는 그림자 품질, 틸트시프트, 파티클, 배경 움직임을 자동으로 줄임.

### 8.2 UX 원칙 (초등학생, 행사장 기준)

- **큰 글씨**(문제 28px 이상), 큰 버튼(최소 80×80px), 한 화면에 할 일 하나.
- **글보다 그림**: 장소마다 대표 그림, 보기에도 그림 활용.
- **시끄러운 행사장**: 소리 없이도 이해되게 시각 효과 우선. 효과음·음성은 볼륨 조절.
- **입력 없이 30초 → 안내, 60초 → 등록 화면으로 자동 복귀**.
- 색약 고려(정답/오답을 색만이 아니라 ⭕❌ 기호로도 표시).
- 별명 입력은 화면 키보드가 지도를 가리지 않도록 **등록 화면을 따로** 둠.

## 11. 행사 운영 계획

- **장비**: 태블릿 2~3대(거치대) 또는 노트북, 전광판용 큰 모니터 1대, 행사장용 무선 인터넷(휴대폰 핫스팟 예비), 보조 배터리, 예비 기기 1대.
- **사전 준비**: 진행자 화면에서 행사 만들기(이름, 기간) → 행사 전용 기관 추가 → 각 기기에서 게임 주소 열고 전체 화면 → 큰 모니터에 전광판 주소.
- **회전**: 1판 5~7분 + 등록 30초 → 기기 1대당 시간당 약 8명.
- **보상 연계**: 결과 화면 등급에 따라 경품 지급. 행사 마감 때 개인 1위·소속 대항전 1위 발표(선택).
- **행사 종료**: 진행자 화면에서 종료 → 리더보드 최종 순위 고정, CSV 내보내기 → 보관 기간 뒤 삭제.
- **데이터 활용**: "문항별 정답률"을 익명으로 뽑아 다음 행사 문항 개선.

## 12. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 지역 사실 오류 | 출처 필드 필수, 군청·역사관 검수, `verified` 없는 문항 차단 |
| 너무 어렵거나 쉬움 | 저/고학년 분리, 시범 운영 정답률 50~80% 목표로 조정 |

| 3D가 태블릿에서 느림 | 기기 성능에 따라 그림자·효과·소품 자동 조절, 시범 운영 때 실기기 측정 |
| 행사장 인터넷 끊김 | 게임 자원 캐시로 계속 플레이, 기록은 대기열에 저장 후 자동 전송 |
| Neon 첫 요청 지연 | 행사 시작 전 전광판을 먼저 켜 두어 DB를 깨워 둠 |
| DB 비밀번호 노출 | 접속 주소는 서버 환경변수에만, 브라우저는 API만 호출 |
| 부적절한 별명 | 금칙어 필터(기기 + 서버), 추천 별명 버튼, 진행자 숨기기 기능 |
| 점수 조작 | 플레이 토큰, 최고점·플레이 시간 검사. 행사용으로 충분한 수준 |
| 개인정보 | 실명·연락처 미수집, 안내 문구, 행사 후 보관 기간 지나면 삭제 |
| 코드 그래픽 품질 편차 | 스타일 시안에서 공통 부품·규칙을 먼저 확정하고 모든 건물에 재사용 |
| 저작권 | 그림·소리는 모두 직접 제작, 글꼴은 라이선스 확인, 원작 게임은 구조만 참고 |

## 13. 결정이 필요한 사항

1. **행사 날짜**: 일정 역산을 위해 필요
2. **소속 목록**: 홍성군 초등학교 외에 미리 넣을 기관·단체
3. **배포 위치**: Vercel(추천) / Netlify / Cloudflare 중 선택, 도메인 사용 여부
4. **공식 캐릭터**: 홍성군 공식 캐릭터를 쓸 수 있는지, 자체 캐릭터(홍이·주니)로 갈지
5. **문항 작성 주체**: 교사 협력이 가능한지, 개발팀이 초안을 쓰고 검수만 받을지
6. **기록 보관 기간**: 행사 종료 후 며칠 뒤 삭제할지
